# 운영 가이드

## 하루 흐름

| 시각 (평일) | 무엇이 | 결과 |
|---|---|---|
| 08:50 | `ktrade run` (작업 스케줄러 ktrade-run) | 장중 매 60초: 시세판 → 매수 조건 확인 → 엔진 손절·익절·보유기간. 15:30 이후엔 대기 |
| 장중 | 매매조건의 매수 타이밍(Entry.after) 이후 매수 판단, 엔진 exits로 매도 | `plan_trades`, `decisions` |
| 16:30 | `ktrade daily` (ktrade-daily) | 수집(`config collect` 범위, 이어받기) → 다음 거래일 계획 → 계획·보유 종목 분봉 |

`ktrade run`은 한 번 띄우면 계속 돕니다. 이미 떠 있으면 작업 스케줄러가 또 띄워도 키움 세션이 겹칠 수 있으니,
작업 스케줄러 설정에서 "이미 실행 중이면 새 인스턴스 시작 안 함"을 확인하세요(기본값).

## 확인할 곳

| 무엇 | 어디 |
|---|---|
| 전체 점검 | `ktrade doctor` |
| 받아 둔 데이터 범위 | `ktrade data`, `ktrade data --symbols 005930` |
| 오늘 상태 | `ktrade status`, `ktrade dashboard` |
| 성적 | `ktrade report` (실행 기록 + 계획 자체 결과, 매매조건 버전별) · 과거 확률은 `ktrade experiments <조건>` |
| 계획 파일 | `~/.ktrade/plans/<기준일>/<조건>.json`, 걸러진 계획·백테스트 안 해서 건너뛴 조건은 `_rejected.json` |
| 로그 | `~/.ktrade/logs/` (`run.log`, `daily.log`, `daily_<날짜>.json`) |

## 휴장일

공휴일 달력을 따로 두지 않습니다. 시세판의 일자가 오늘이 아니면 휴장으로 보고 매매하지 않고, 주문이 거부돼도 다음 거래일에 다시 시도합니다.
계획은 'DB의 오늘 이전 마지막 거래일'을 기준일로 만든 것만 실행합니다 — `daily`가 하루 빠지면 묵은 계획으로 매매하지 않습니다.

## 매매조건 고치기

조건·파라미터·청산 설정 중 무엇이든 바꾸면 `ktrade test <조건>`을 다시 돌리세요 — 실험이 쌓이고 직전과 비교됩니다.
`strategies.require_backtest: true`(기본)면 지금 설정으로 실험한 기록이 없는 조건은 계획을 만들지 않습니다.
규칙 자체를 바꿨으면 `strategy.yaml`의 `version`도 올리세요(실제 매매 기록이 버전별로 남음).
모의 매매는 건수가 적습니다 — 손실 한 건마다 조건을 고치지 말고, 실험(앞·뒤 기간 일관성)으로 확인한 뒤 바꾸세요.

## 백업

`~/.ktrade/` 폴더 하나(설정·데이터·계획·내 전략)를 통째로 복사하면 됩니다. `.env`(키)는 백업 위치도 안전하게.

## 문제가 생기면

| 증상 | 확인 |
|---|---|
| 키움 API 연결 실패 | `.env` 키, 모의/실전 키 구분, 키움 OpenAPI 사이트의 사용 신청 상태 |
| 계획이 안 생김 | `ktrade doctor`(시세 날짜, '백테스트 필요' 표시), `plans/<기준일>/_rejected.json`, `logs/daily_<날짜>.json` |
| 매수가 안 됨 | `decisions`의 `PLAN_SKIP`/`PLAN_WAIT` 사유 (시가 조건, 매수 구간, 리스크 한도) |
| 매도 주문이 걸려만 있음 | 지정가 = 현재가 ± `risk.order_slippage_pct`. 급변 종목은 값을 키워 보세요 |
